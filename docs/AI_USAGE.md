# AI Tool 활용 로그 (심사 기준 대응)

심사 노트: “AI/보드를 빼도 작품이 성립하면 활용도 점수가 낮다.”
이 프로젝트는 **두 층**으로 답한다.

## 1. 제품 안의 AI (점수에 해당하는 층)

| 단계 | 모델 | 빼면 |
|---|---|---|
| 정합 | DISK 키포인트 + LightGlue 매칭 (kornia, 사전학습) | 이종 소스(NAIP→Maxar) 인라이어가 1/10 수준. 타일 절반이 매칭 공백. |
| 피해 점수 | 학습 분류기 없음. ΔNDVI + SSIM | 이 층은 고전 원격탐사. 정합이 어긋나면 허위 변화가 점수로 들어간다. |
| 검증 | 없음 (DINS는 현장조사) | — |

주장: 챗봇을 붙인 게 아니라, **매칭이 제품의 핵심 가치**다. 수치는 `results/registration_metrics.csv`.

## 2. 개발 과정에서 쓴 AI 도구

| 도구 | 한 일 | 사람이 한 일 |
|---|---|---|
| Cursor (에이전트) | STAC 수집, LightGlue/SIFT 파이프라인, NAIP 워프, DINS 조인, Streamlit, 슬라이드 렌더 | 문제 선정(GRS Lab 정합), 이종 소스 실험 결정, 한계 문장, 발표 스토리 |
| kornia 사전학습 가중치 | DISK depth 체크포인트, LightGlue disk 가중치 자동 다운로드 | 학습 데이터 구축·파인튜닝은 하지 않음 |
| 쓰지 않은 것 | GPT로 피해를 “설명해 주는” 챗봇, 이미지 생성으로 가짜 산불 영상 | — |

발표에서 한 문장: “개발에도 코딩 에이전트를 썼고, 제품 가치는 학습 매칭이 이종 영상을 맞추는 데 있다. 후자를 빼면 숫자가 무너진다.”
